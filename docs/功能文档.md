# Hermes Lib · 功能文档

> 版本 1.0.0 ｜ 目标环境 Minecraft 26.3 + Carpet 26.3 + Fabric Loader 0.19.5 + Java 25
> 文档定位：**面向使用者与下游集成方的功能说明**。本模组只负责「采集 + 存储 + 暴露接口」，
> 所有查询、排行、展示、奖励逻辑由下游实现。

---

## 0. 一句话说明

Hermes Lib 监听游戏行为 → 按「真实玩家 / 假人」分域累计 → 落盘到世界内的 SQLite →
通过 Java API（可选 Scarpet 函数）把数据交给你。

**它不做的事**（刻意为之）：不提供任何查询命令、不做排行榜、不做计分板 / HUD / Tab / 聊天栏展示、
不做分页、不做玩家交互 UI、不做奖励结算。你拿到的只有数据。

## 2. 规则清单

规则由 Carpet 的扩展设置管理器托管：

* 命令：`/hermes`（**只能开关采集行为**，没有任何查询子命令）
* 配置文件：`<世界>/hermes.conf`
* 分类：`ranking`（`/hermes` 面板里的「数据统计」分类）

| 规则名 | 默认 | 作用 | 关闭后的影响 |
|---|---|---|---|
| `rankingEnabled` | `true` | 总开关 | 所有维度停止采集（规则本身保留） |
| `rankingTrackPlayTime` | `true` | 在线时长 | `playtime_ticks` / `playtime_seconds` 停止累加 |
| `rankingTrackBlocksMined` | `true` | 挖掘量 | `blocks_mined` 停止累加 |
| `rankingTrackBlocksPlaced` | `true` | 放置量 | `blocks_placed` 停止累加 |
| `rankingTrackMobKills` | `true` | 生物击杀 | `mob_kills` 停止累加 |
| `rankingTrackPlayerKills` | `true` | 玩家击杀 | `player_kills` 停止累加 |
| `rankingTrackDeaths` | `true` | 死亡数 | `deaths` 停止累加 |
| `rankingTrackVillagerTrades` | `true` | 村民交易 | `villager_trades` 停止累加 |
| `rankingTrackFishCaught` | `true` | 钓获次数 | `fish_caught` 停止累加 |
| `rankingTrackElytraDistance` | `true` | 鞘翅距离 | `distance_elytra` 停止累加 |
| `rankingTrackDamageDealt` | `true` | 造成伤害 | `damage_dealt` 停止累加 |
| `rankingTrackDamageTaken` | `true` | 受到伤害 | `damage_taken` 停止累加 |
| `rankingTrackMovement` | `true` | 移动距离 | 5 个 `distance_*` 与 `distance_total` 全部停止 |
| `rankingTrackItemsCrafted` | `true` | 合成产出 | `items_crafted` 停止累加 |
| `rankingTrackItemsPickedUp` | `true` | 拾取物品 | `items_picked_up` 停止累加 |
| `rankingTrackItemsDropped` | `true` | 丢弃物品 | `items_dropped` 停止累加 |
| `rankingTrackItemsUsed` | `true` | 使用物品 | `items_used` 停止累加 |
| `rankingTrackItemsBroken` | `true` | 耐久 / 损坏 | `items_damaged` / `items_broken` 停止累加 |
| `rankingTrackAnimalsBred` | `true` | 动物繁殖 | `animals_bred` 停止累加 |
| `rankingTrackAnimalsTamed` | `true` | 驯服 | `animals_tamed` 停止累加 |
| `rankingTrackEnchantments` | `true` | 附魔 | `enchantments` 停止累加 |
| `rankingTrackJumps` | `true` | 跳跃 | `jumps` 停止累加 |
| `rankingMinedNaturalOnly` | `true` | 只统计自然方块 | 改为统计玩家放置后挖掉的方块 |
| `rankingSeparateFakePlayers` | `true` | 假人独立数据域 | 假人数据改写入 REAL 域（UUID 仍独立，不覆盖真人） |

> 关闭某个维度后，对应 Mixin 命中即 return，**不产生任何计数开销**（只多一次布尔判断）。

## 3. 指标清单（27 个）

`metric` 取值是**稳定契约**，可直接写进下游 SQL；只增不改。

### 3.1 时间

| metric | 单位 | 含义 |
|---|---|---|
| `playtime_ticks` | tick | 在线 tick 数（20 tick = 1 秒） |
| `playtime_seconds` | 秒 | 在线秒数 |

### 3.2 方块

| metric | 单位 | 含义 |
|---|---|---|
| `blocks_mined` | 个 | 破坏的方块数（受 `rankingMinedNaturalOnly` 影响） |
| `blocks_placed` | 个 | 放置的方块数 |

### 3.3 战斗

| metric | 单位 | 含义 |
|---|---|---|
| `mob_kills` | 次 | 击杀生物数（近战 / 投射物 / 驯服生物攻击，均归属攻击者） |
| `player_kills` | 次 | 击杀玩家数 |
| `deaths` | 次 | 死亡次数 |
| `damage_dealt` | 点 | 造成伤害（护甲/抗性结算后的值，四舍五入） |
| `damage_taken` | 点 | 受到伤害（同上口径） |

### 3.4 交互与物品

| metric | 单位 | 含义 |
|---|---|---|
| `villager_trades` | 笔 | 村民成交笔数 |
| `fish_caught` | 次 | 收竿钓起战利品的次数（含鱼/宝藏/垃圾） |
| `items_crafted` | 个 | 合成产出物品数量 |
| `items_picked_up` | 个 | 从地面捡起的物品数量 |
| `items_dropped` | 个 | 主动丢弃（Q 键）的物品数量；死亡掉落**不计入** |
| `items_used` | 次 | 使用物品次数（吃东西、举盾、拉弓等） |
| `items_damaged` | 次 | 耐久损耗事件次数 |
| `items_broken` | 个 | 彻底损坏（碎裂）的工具/装备数量 |

### 3.5 生物

| metric | 单位 | 含义 |
|---|---|---|
| `animals_bred` | 次 | 动物繁殖次数（归属到喂食者） |
| `animals_tamed` | 次 | 驯服次数 |

### 3.6 移动（单位统一为**厘米**，1 格 = 100）

| metric | 含义 |
|---|---|
| `distance_walk` | 步行距离（不含疾跑） |
| `distance_sprint` | 疾跑距离 |
| `distance_swim` | 游泳距离 |
| `distance_ride` | 骑乘距离 |
| `distance_elytra` | 鞘翅飞行距离 |
| `distance_total` | 水平移动总距离（= 上面五项之和） |

> 五个分档**互斥**：每 tick 的位移只计入优先级最高的一档
> （鞘翅 → 骑乘 → 游泳 → 疾跑 → 步行），因此 `distance_total` 等于五项之和。
> 单 tick 位移超过 50 格视为传送，直接丢弃。

### 3.7 其它

| metric | 单位 | 含义 |
|---|---|---|
| `enchantments` | 次 | 施加附魔次数 |
| `jumps` | 次 | 跳跃次数 |

## 4. 数据域与假人

### 4.1 两个数据域

| domain | 含义 |
|---|---|
| `REAL` | 真实玩家 |
| `FAKE` | 假人（Carpet 假人 / Fabric 通用假人） |

### 4.2 识别方式：**按类型，不按 UUID**

```java
player instanceof carpet.patches.EntityPlayerMPFake        // Carpet 假人
player instanceof net.fabricmc.fabric.api.entity.FakePlayer // Fabric 通用假人（反射探测）
```

原因：Fabric 规范允许通用假人与真人**共享同一个 UUID**，用「UUID 在不在玩家列表里」判断必然出错。

### 4.3 UUID 归一（防覆盖）

| 玩家类型 | 写入时使用的 UUID |
|---|---|
| 真人 | 自身 UUID |
| Carpet 假人 | 自身 UUID（Carpet 为每个假人生成独立 UUID） |
| Fabric 通用假人 | 由「归属者 UUID + 假人名」派生的稳定伪 UUID |

因此**即使把 `rankingSeparateFakePlayers` 关掉**（假人写进 REAL 域），假人也绝不会覆盖真人数据。

### 4.4 切换域时的历史数据

修改 `rankingSeparateFakePlayers` 后，同一 UUID 的历史数据仍留在原数据域（不会被搬迁）。
这是有意设计：域切换本身是一种可审计的语义变更，历史数据不应被静默改写。

## 5. 存储

### 5.1 位置与文件

* 路径：`<世界>/ranking-stats.db`（随世界保存、随世界迁移）
* 运行期伴随 `ranking-stats.db-wal` / `ranking-stats.db-shm`
* 关闭服务端时会把 WAL checkpoint 回主库并截断

### 5.2 表结构

```sql
CREATE TABLE IF NOT EXISTS player_stats (
    uuid   TEXT    NOT NULL,
    domain TEXT    NOT NULL,              -- 'REAL' / 'FAKE'
    metric TEXT    NOT NULL,
    value  INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (uuid, domain, metric)
);

CREATE INDEX IF NOT EXISTS idx_metric_domain_value
    ON player_stats(metric, domain, value DESC);

-- 附赠：玩家名索引，方便下游按名字排行
CREATE TABLE IF NOT EXISTS player_names (
    uuid      TEXT    NOT NULL,
    name      TEXT    NOT NULL,
    last_seen INTEGER NOT NULL,
    PRIMARY KEY (uuid)
);
```

长表设计的意义：加新指标只需 INSERT 一行、**不需要改表结构**；下游可以直接写 SQL 排行，
不必引入 Java 端。

### 5.3 落库时机与语义

| 时机 | 行为 |
|---|---|
| 每 5 分钟（6000 tick） | 全量落库 |
| 玩家退出 | 落库该玩家 |
| 服务器关闭 | 全量落库 → checkpoint → 关连接 |

写入使用**绝对值覆盖**（UPSERT），因此重复落库是幂等的；写失败只记日志，不影响游戏线程，
下一次落库会全量覆盖修正。

## 6. 对外接口

### 6.1 Java API

```java
import hermeslib.api.*;          // DataDomain / Metric / RankingDataProvider / HermesApi

RankingDataProvider stats = HermesApi.provider();   // 服务器加载完成后可用
```

| 方法 | 返回 | 说明 |
|---|---|---|
| `getValue(uuid, domain, metric)` | `long` | 单指标值，无记录返回 0 |
| `getValue(uuid, domain, "blocks_mined")` | `long` | 按指标名字符串取，非法名返回 0 |
| `getAll(uuid, domain)` | `Map<Metric, Long>` | 该玩家该域的全部指标 |
| `getTotal(uuid, domain)` | `long` | 该玩家该域的指标总和（可自定义「综合分」） |
| `top(metric, domain, limit)` | `List<RankedEntry>` | 某指标前 N 名，`RankedEntry(uuid, name, value)` |
| `getName(uuid)` | `Optional<String>` | 最后已知名称 |
| `findByName(name)` | `Optional<UUID>` | 按名字查 UUID（在线玩家 + 历史记录） |
| `domainOf(player)` | `DataDomain` | 该实体当前属于哪个域 |
| `effectiveUuid(player)` | `UUID` | 该实体写入数据库时使用的 UUID |
| `knownPlayers()` | `Collection<UUID>` | 所有已知玩家 |

辅助入口：`HermesApi.provider()`（可能为 null）、`HermesApi.isReady()`、`HermesApi.require()`（未就绪抛异常）。

> 线程约定：所有方法在服务器主线程调用，实现内部线程安全。

### 6.2 Scarpet 函数（可选）

```
ranking_data('Steve', 'blocks_mined')          # REAL 域
ranking_data('Steve', 'blocks_mined', 'FAKE')  # 指定数据域
ranking_total('Steve')                         # REAL 域全部指标之和
ranking_total('Steve', 'FAKE')                 # 指定域
```

找不到玩家或指标名非法时返回 `0`。函数注册为 impure（结果随时间变化，不会被 Scarpet 缓存）。

### 6.3 直接读 SQLite

```sql
-- 挖掘榜前 10
SELECT p.name, s.value
FROM player_stats s
JOIN player_names p ON p.uuid = s.uuid
WHERE s.metric = 'blocks_mined' AND s.domain = 'REAL'
ORDER BY s.value DESC LIMIT 10;

-- 假人与真人分开看
SELECT domain, COUNT(*) FROM player_stats GROUP BY domain;
```

## 7. 典型集成场景

| 场景 | 做法 |
|---|---|
| 另一模组做排行榜 | 依赖 Hermes Lib，取 `HermesApi.provider()`，自己画 UI / 发奖励 |

| 定时备份 | 复制 `ranking-stats.db` + `-wal`（或先优雅关服再复制） |

## 8. 运维要点

* **性能**：热路径只有一次开关判断 + 一次 `LongAdder.add`；所有 JDBC 都在独立线程，
  主线程永不阻塞在磁盘 IO 上。
* **内存**：每个（玩家 × 域）一份指标数组；放置追踪最多 20 万条、30 分钟过期。
* **磁盘**：随玩家数与指标数线性增长，`value` 为 8 字节整数。
* **降级**：数据库打不开 / 读失败 / 写失败都只记日志，模组继续以内存数据运行，不会崩服。
* **调试**：加 `-Dhermes.debug=true` 会输出采集、落库、以及「启动时预热全部 Mixin 目标类」
  的结果（可提前发现注入点写错的问题）。不加则完全静默。

## 9. 已知边界与精度取舍

1. **距离用整数厘米**，避免浮点误差；单 tick 超过 50 格视为传送并丢弃。
2. **伤害取 `actuallyHurt` 的结算值**（护甲/抗性结算后），不区分伤害吸收。
3. **附魔归属**靠「10 秒内最近一次使用过附魔台/铁砧的玩家」；若某条附魔路径不经过
   `ItemStack#enchant`，该次附魔可能漏计。
4. **繁殖归属**靠「60 秒内与该动物交互过的玩家」，兜底取 8 格内最近的玩家。
5. **放置记录只在内存**，服务重启后清空：「重启前放置、重启后挖掉」的方块会被当作自然方块。
6. **死亡掉落不计入 `items_dropped`**（只统计玩家主动丢弃）。
7. **钓鱼**按「收竿钓起战利品」计一次，不是按鱼的数量。

## 10. 部署

1. 服务器安装 **Carpet 26.3** 与本模组（`hermes-lib-1.0.0.jar`）。
2. 启动后自动创建 `<世界>/ranking-stats.db` 与 `<世界>/hermes.conf`。
3. 用 `/hermes rankingEnabled false` 可整体停采；用 `/hermes rankingTrackBlocksMined false`
   可单独关掉某个维度。
4. 自测：把 `selftest/datapack/hermestest` 放进世界 `datapacks/` 后重启，可验证
   假人生成、移动、受伤、死亡四个链路（详见 `selftest/README.md`）。
